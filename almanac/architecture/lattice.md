# Semantic Lattice

The semantic lattice is a folder of markdown documentation generated by the
gateway at boot and regenerated whenever the graph changes. It lives at
`.mcp_lattice/` and contains:

- `skills.md` — list of all active servers with descriptions
- `relations.md` — the capability relationship graph in compact format
- `<server>_readme.md` — README documentation fetched from GitHub for each server

## Generation

`GenerateLattice()` (defined in \`internal/docs/lattice.go\`) is called at boot and after every graph rebuild [@lattice_pkg]. It:

1. Creates the lattice directory
2. Writes `skills.md` with all server names and descriptions
3. Writes `relations.md` with the compact graph representation
4. Spawns background goroutines to fetch READMEs from GitHub for HTTP/SSE
   servers, or from NPM for stdio servers using `npx`

## Directory

The lattice directory is resolved by `defaultLatticeDir()` (`cmd/util.go`) and
threaded through `--lattice-dir` from `cmd/serve.go` [@serve_lattice] — it is not hardcoded in
the gateway [@lattice_dir_adr]. By default the path is
`os.UserCacheDir()/skillgraph-mcp/lattice`:

| OS | Default location |
|---|---|
| macOS | `$HOME/Library/Caches/skillgraph-mcp/lattice` |
| Linux | `$XDG_CACHE_HOME/skillgraph-mcp/lattice` or `~/.cache/skillgraph-mcp/lattice` |
| Windows | `%LocalAppData%\skillgraph-mcp\lattice` |

If `os.UserCacheDir()` fails (e.g. `$HOME` unset), it falls back to the
CWD-relative `./.mcp_lattice` and logs a warning [@lattice_dir_util]. The CWD-relative path
remains reachable explicitly via `--lattice-dir ./.mcp_lattice` (debug, tests,
ephemeral runs). Because the default is a per-user cache path, running the
binary from different working directories no longer scatters traces across
them.

The directory holds `skills.md`, `relations.md`, per-server `<server>_readme.md`
(or a `.noreadme` sentinel), trajectory files under `traces/`, and rollback
snapshots under `history/`.

## Rollback Snapshots

Before each SkillOpt edit the refine engine writes a snapshot of `mcp.json`'s
`skillGraph` section to `<latticeDir>/history/skillgraph_*.json` and trims
`history/` to the 5 most recent [@refine_snapshot]. If an edit fails the
1.5x rollback gate, `rollbackToLatestSnapshot()` restores the most recent
snapshot.

## README Fetching

For each server, the lattice generator attempts to fetch README documentation:

- **HTTP/SSE servers** with `github.com` in the URL → fetches the GitHub README
- **Stdio servers** using `npx` → extracts the NPM package name and fetches
  its README from the NPM registry

If fetching fails, a sentinel file (`<server>_readme.md.noreadme`) is written
so the bootstrap refinement loop knows not to wait indefinitely.

## NPM Package Extraction

`extractNPMPackage()` recognizes plain `npx` commands, absolute paths to npx,
and wrapper scripts whose basename starts with `npx` (e.g., `npx-mcp`).
It extracts the package name from the first positional argument, handling
scoped packages (`@scope/package`) and version suffixes.

## Gotchas

- The lattice directory is resolved by `defaultLatticeDir()` (`cmd/util.go`) to
  a per-user cache path by default, so running the binary from different
  working directories no longer scatters traces. The CWD-relative
  `./.mcp_lattice` is reachable only via `--lattice-dir`, and as a fallback
  when `os.UserCacheDir()` fails (for example, `$HOME` unset) [@lattice_dir_util].
- README fetching happens in background goroutines. The bootstrap refinement
  loop waits up to 15 seconds for each README before proceeding with tools
  only.
- The lattice is regenerated after every graph rebuild (via SkillOpt or manual
  edits). Manual edits to lattice files will be overwritten.
